<p>When a task fails, Kroma shows a red note at the bottom of the window with a title like <strong>Download failed</strong> or <strong>Export failed</strong>, and the reason underneath. It&#39;s also kept in the <a href="/kroma/docs/0.2/notifications/">bell</a> in the title bar, so you can read it later, and often has a <strong>Retry</strong> button. The sections below are sorted by that task.</p>
<h2 id="installing-and-opening"><a class="anchor" href="#installing-and-opening" aria-hidden="true">#</a>Installing and opening</h2><h3 id="macos-kroma-studio-is-damaged-or-it-won-t-open"><a class="anchor" href="#macos-kroma-studio-is-damaged-or-it-won-t-open" aria-hidden="true">#</a>macOS: &quot;Kroma Studio is damaged&quot; or it won&#39;t open</h3><p>Kroma isn&#39;t signed with an Apple certificate yet, so macOS blocks it the first time. Move it into <strong>Applications</strong>, then run this once in Terminal:</p>
<div class="code-block"><pre><code class="language-bash">xattr -cr &quot;/Applications/Kroma Studio.app&quot;</code></pre></div><p>Then open it again. See <a href="/kroma/docs/0.2/installation/#macos">Installation</a>.</p>
<h3 id="windows-windows-protected-your-pc"><a class="anchor" href="#windows-windows-protected-your-pc" aria-hidden="true">#</a>Windows: &quot;Windows protected your PC&quot;</h3><p>The installer isn&#39;t code-signed yet. Click <strong>More info</strong>, then <strong>Run anyway</strong>.</p>
<h3 id="linux-the-appimage-does-nothing"><a class="anchor" href="#linux-the-appimage-does-nothing" aria-hidden="true">#</a>Linux: the AppImage does nothing</h3><p>Make it executable first:</p>
<div class="code-block"><pre><code class="language-bash">chmod +x Kroma-Studio-*.AppImage &amp;&amp; ./Kroma-Studio-*.AppImage</code></pre></div><p>Or install the <code>.deb</code> instead.</p>
<h3 id="i-open-kroma-but-no-new-window-appears"><a class="anchor" href="#i-open-kroma-but-no-new-window-appears" aria-hidden="true">#</a>I open Kroma but no new window appears</h3><p>Kroma only runs once. Opening it again brings the open window to the front. To work on a second project, use <strong>File → New Window</strong> (⇧⌘N / Ctrl+Shift+N). See <a href="/kroma/docs/0.2/projects-and-files/#only-one-kroma-at-a-time">Projects and files</a>.</p>
<p>On a Mac, Kroma keeps running after you close its last window. Click the Dock icon to get a window back.</p>
<h2 id="missing-ffmpeg-or-yt-dlp"><a class="anchor" href="#missing-ffmpeg-or-yt-dlp" aria-hidden="true">#</a>Missing FFmpeg or yt-dlp</h2><p>A red bar at the top of the editor says <strong>Missing ffmpeg, ffprobe, yt-dlp. Install with:</strong> and shows the command for your system. <strong>Settings → About → Tools</strong> shows the same thing, tool by tool.</p>

<p>More tips:</p>
<ul>

<li><strong>Safari logins don&#39;t work?</strong> Safari also needs Full Disk Access: macOS <strong>System Settings → Privacy &amp; Security → Full Disk Access</strong>, turn on Kroma Studio.</li>
<li><strong>A site that used to work stopped working?</strong> Sites change often. On Windows and Linux, update Kroma: its yt-dlp is updated with it. On a Mac, run <code>brew upgrade yt-dlp</code>.</li>

<h3 id="some-lines-weren-t-translated"><a class="anchor" href="#some-lines-weren-t-translated" aria-hidden="true">#</a>Some lines weren&#39;t translated</h3><p>&quot;Translated … of … lines&quot; with &quot;… need another try.&quot; Press <strong>Translate missing</strong> on the notice, or <strong>Only missing</strong> in <strong>Translate → Step by step</strong>. It only sends the lines that are still empty.</p>
<h3 id="no-speech-was-found"><a class="anchor" href="#no-speech-was-found" aria-hidden="true">#</a>&quot;No speech was found.&quot;</h3><p>Speech to text heard nothing it could write down. Check the video has speech, and that <strong>Spoken language</strong> in the <strong>Translate</strong> panel is right.</p>
<h2 id="voices"><a class="anchor" href="#voices" aria-hidden="true">#</a>Voices</h2><h3 id="can-t-reach-the-voice-engine-at"><a class="anchor" href="#can-t-reach-the-voice-engine-at" aria-hidden="true">#</a>&quot;Can&#39;t reach the voice engine at …&quot;</h3><p>Designed and cloned voices need the voice engine to be running. Open <a href="/kroma/docs/0.2/settings/#voice-engine">Settings → Voice Engine</a> and press <strong>Start engine</strong> (or <strong>Install voice engine</strong> first if it says &quot;Not installed&quot;), then press <strong>Check</strong>. If you use Colab, keep its notebook running and check the address. A Colab address changes every time you start the notebook, so paste the new one. Or use the instant voices, which don&#39;t need the engine. See <a href="/kroma/docs/0.2/voice-engine/">The voice engine</a>.</p>
<h3 id="the-voice-engine-refused-the-token"><a class="anchor" href="#the-voice-engine-refused-the-token" aria-hidden="true">#</a>&quot;The voice engine refused the token.&quot;</h3><p>Copy the token the Colab notebook prints into <strong>Settings → Voice Engine → Token</strong>.</p>
<h3 id="instant-voices-fail"><a class="anchor" href="#instant-voices-fail" aria-hidden="true">#</a>Instant voices fail</h3><p>&quot;The voice service didn&#39;t answer. Check your internet and try again.&quot; or &quot;The voice service timed out&quot;. The instant voices come from an online service. Check your internet and press <strong>Make voice-over</strong> again. Lines already done are kept.</p>
<h3 id="voiced-lines-not-done-press-again-to-finish-them"><a class="anchor" href="#voiced-lines-not-done-press-again-to-finish-them" aria-hidden="true">#</a>&quot;Voiced … lines; … not done. Press again to finish them.&quot;</h3><p>Press the voice-over button in the <strong>Voice</strong> panel again (it then reads <strong>Voice the … new lines</strong>). It only makes the lines that are missing.</p>
<h3 id="i-still-hear-the-original-voices"><a class="anchor" href="#i-still-hear-the-original-voices" aria-hidden="true">#</a>I still hear the original voices</h3><ul>
<li>Check that <strong>Voice → Mix → Remove the original voices</strong> is on.</li>
<li>Removing voices needs <a href="/kroma/docs/0.2/installation/">uv</a>. Without it you see &quot;Removing voices needs uv. Install it with: …&quot;. <strong>Settings → About → Tools</strong> shows the command for your system.</li>
<li>The first time, Kroma downloads the voice-removal tool and model. That can take a while: wait for it to finish.</li>
<li>If removing fails, Kroma says &quot;The original voices are still in&quot;. Try again from <strong>Voice → Mix</strong>, then export again.</li>
</ul>
<h3 id="the-microphone-doesn-t-work-mac"><a class="anchor" href="#the-microphone-doesn-t-work-mac" aria-hidden="true">#</a>The microphone doesn&#39;t work (Mac)</h3><p>&quot;Kroma isn&#39;t allowed to use the microphone. Turn it on in System Settings → Privacy &amp; Security → Microphone, then try again.&quot; Press <strong>Open Microphone settings</strong>, turn on Kroma Studio, and try again.</p>
<h2 id="exporting"><a class="anchor" href="#exporting" aria-hidden="true">#</a>Exporting</h2><h3 id="an-export-fails"><a class="anchor" href="#an-export-fails" aria-hidden="true">#</a>An export fails</h3><p>When an export fails, Kroma saves the full details in a file called <code>last-export-error.log</code> in its settings folder:</p>
<div class="table-wrap"><table>
<thead>
<tr>
<th>System</th>
<th>File</th>
</tr>
</thead>
<tbody><tr>
<td>macOS</td>
<td><code>~/Library/Application Support/Kroma Studio/last-export-error.log</code></td>
</tr>
<tr>
<td>Windows</td>
<td><code>%APPDATA%\Kroma Studio\last-export-error.log</code></td>
</tr>
<tr>
<td>Linux</td>
<td><code>~/.config/Kroma Studio/last-export-error.log</code></td>
</tr>
</tbody></table></div>
<p>Each failed export replaces it. Attach it when you <a href="#reporting-a-problem">report the problem</a>.</p>
<p>Things to check first:</p>
<ul>
<li><strong>&quot;The timeline is empty.&quot;</strong> Add a video to the timeline.</li>
<li><strong>A video, image or voice file was moved or deleted.</strong> The project only points to its files. Put them back where they were. See <a href="/kroma/docs/0.2/projects-and-files/#the-project-file">Projects and files</a>.</li>
<li><strong>The disk is full.</strong> Free some space, or <a href="/kroma/docs/0.2/projects-and-files/#clearing-space">clear Kroma&#39;s cache</a>.</li>
<li><strong>&quot;Some lines have no voice yet; they&#39;ll be silent.&quot;</strong> This isn&#39;t an error. Press <strong>Make voice-over</strong> before exporting to fill them.</li>
</ul>
<h3 id="export-is-slow"><a class="anchor" href="#export-is-slow" aria-hidden="true">#</a>Export is slow</h3><p><strong>High</strong> takes about three times as long as <strong>Standard</strong>. On a Mac, <strong>Standard</strong> is the fastest because it uses the Mac&#39;s video chip. See <a href="/kroma/docs/0.2/export/">Export</a>.</p>

<h2 id="reporting-a-problem"><a class="anchor" href="#reporting-a-problem" aria-hidden="true">#</a>Reporting a problem</h2><p>If none of this helps, <a href="https://github.com/Heang-Dev/KROMA.STUDIO/issues" target="_blank" rel="noreferrer">open an issue on GitHub</a>. Include:</p>
<ol>
<li>Your Kroma version: <strong>Settings → About</strong> shows it, for example <strong>Kroma Studio 0.2.0</strong>.</li>
<li>Your system: macOS, Windows or Linux, and its version.</li>
<li>What you did, what you expected, and the exact message Kroma showed.</li>
<li>For an export problem, attach <code>last-export-error.log</code> (see <a href="#an-export-fails">An export fails</a>).</li>
<li>For a download problem, the link you used, if it&#39;s public.</li>
</ol>
<p>Kroma doesn&#39;t keep other log files, so the message on screen is the most useful thing to copy.</p>
<p><strong>Never</strong> paste your API keys into an issue, and don&#39;t attach <code>settings.json</code>.</p>
